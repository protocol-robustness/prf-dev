# Routine signing policy and pilot limits

`schemas/routine-trust-policy.v1.json` defines the versioned public-key roster used by the routine submission pilot. Keep the authoritative copy in access-controlled dev-ops configuration and provide it independently to each signer and verifier. The digest of its deterministic JSON encoding is copied into each signed record. Do not accept a trust policy from the candidate bundle itself.

Generate Ed25519 keys with OpenSSH (`ssh-keygen -t ed25519`). Keep each private key outside agent workspaces, candidate repositories, logs, and artifacts. Assign separate principals and OS identities to coding, review, and staging. A public key must appear only in the role(s) and repository scope it is authorized for. The verifier rejects inactive keys, role mismatches, repository mismatches, repeated principals, and changed policy roots. It does not itself enforce OS-user separation or protect keys from another process running as the same OS user; use a restricted signing broker or separate account boundaries before production use.

For rotation, publish a new policy version with the replacement key and an explicit effective time in the surrounding operator change record. Retain prior policy snapshots for historical verification; do not edit old snapshots in place. For revocation, mark the principal revoked in the current policy and distribute the replacement policy. Current verification fails closed for revoked keys, so historical verification against an old policy must be reported as such and must not be represented as current authorization.

Routine signed records are credential attestations, not proof that a specific model or process acted. `routine stage --tests` accepts names of checks asserted by the staging signer; the pilot does not execute or independently validate those commands. Production integration must only issue the staging signature after the owning staging workflow has run and recorded its checks. Current Symphony agents are not yet wired to invoke these commands or to obtain isolated signing operations. Legacy unsigned submissions remain unsigned and must not be backfilled as signed.
